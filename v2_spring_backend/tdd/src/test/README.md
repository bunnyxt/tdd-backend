# PHP compatibility contract tests

Run with JDK 11:

```sh
mvn -B test
```

The suite starts the full application on a random local port, with an isolated H2
database and a stub Bilibili client. It does not connect to production or Bilibili.
It compares JSON field types, nulls, array order, missing fields and wrappers in
59 cases, and checks wildcard CORS, OPTIONS/POST, unchanged existing-route CORS,
SQL binding, silent query failures and complete 12,004-row history responses.

`resources/legacy/fixture.json` contains only invented records and upstream
responses. Expected bodies were generated by PHP 7.0.33 executing the repository's
v1 endpoint/model/query code with an in-memory database adapter. The production
record endpoint's positive-aid guard is applied explicitly by the generator.
No connection file or credentials are loaded.

From the repository root, regenerate using PHP 7.0:

```sh
python3 v2_spring_backend/tdd/src/test/legacy_reference.py --php /path/to/php7.0
```

Or use `--emit-programs` to emit a JSON array of self-contained PHP programs for
execution in a PHP 7.0 environment. Each program must run in a separate process
because the legacy endpoints call `die()`.

The PHP adapter supports the legacy queries' equality/range/order/limit syntax.
It is not a MySQL emulator: SQL execution is separately exercised using H2 in
MySQL mode, and MySQL query plans/production behavior require deployment checks.

History responses use Connector/J forward-only streaming into an automatically
deleted private temporary JSON file. This avoids retaining the complete result
in heap and releases the database connection before transfer to a slow client.
Positive limits select the newest N rows then return them in ascending id order;
zero/negative limits preserve the entire selected history. Temporary disk space
and client bandwidth still grow with the response size.
